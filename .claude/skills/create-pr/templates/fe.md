# PR 템플릿 — FE 개발자 (로직/상태 구현)

> 이 템플릿은 **초안(draft)**이다. 실제 팀 컨벤션이 확정되면 이 파일을 그 내용으로 갱신하라.
> 프로젝트의 `CLAUDE.md`/`AGENTS.md`에 이미 PR 관련 규칙이 있다면 그쪽이 우선한다.
> 이 저장소에서 유틸/훅 작업을 할 때는 `.claude/rules/tdd.md`도 함께 적용된다 — PR을 올리기 전 RED-GREEN-REFACTOR가 지켜졌는지 확인하라.

## 적용 대상

상태 관리, API 연동, 비즈니스 로직, 훅/컴포넌트 로직 변경. 마크업·스타일만 바꾼 변경은 `publisher.md` 템플릿을 따르라.

## PR 제목

```
[FE] <type>: <한 줄 요약>
```

`type`은 저장소 커밋 컨벤션과 동일하게 `feat`/`fix`/`refactor`/`chore` 중 선택한다.

## PR 본문 템플릿

```markdown
## 변경 사항
- 무엇을/왜 변경했는지

## 테스트
- [ ] 관련 테스트를 추가/수정했다
- [ ] 프로젝트 테스트 명령 통과 확인 (예: `bun run test`)
- [ ] 린트 통과 확인 (예: `bun run lint`)
- [ ] 타입 체크 통과 확인 (해당 시)

## 체크리스트
- [ ] 엣지 케이스(빈 값, 에러 응답, 로딩 상태)를 처리했다
- [ ] 불필요한 리렌더·중복 요청이 없는지 확인했다
- [ ] 관련 이슈/티켓을 링크했다
```

## 리뷰어

FE 팀 동료 1인 이상.

## 강제하지 않는 것

- 디자인 시안과의 픽셀 단위 비교 (순수 로직 변경이면 생략 가능)
