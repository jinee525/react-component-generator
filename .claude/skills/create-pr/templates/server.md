# PR 템플릿 — 서버 개발자 (API/백엔드 로직)

> 이 템플릿은 **초안(draft)**이다. 실제 팀 컨벤션이 확정되면 이 파일을 그 내용으로 갱신하라.
> 프로젝트의 `CLAUDE.md`/`AGENTS.md`에 이미 PR 관련 규칙이 있다면 그쪽이 우선한다.
> 이 저장소에서 서버 로직(예: `server/`)을 다룰 때는 `server/AGENTS.md`의 Golden Rules(순수 함수/side-effect 분리, API 키 보안 경계 등)도 함께 확인하라.

## 적용 대상

API 엔드포인트, 서버 로직, DB 접근·마이그레이션, 인증/인가, 외부 서비스 연동 등 백엔드 변경. UI/마크업 변경은 `publisher.md`, 프론트 로직 변경은 `fe.md` 템플릿을 따르라.

## PR 제목

```
[BE] <type>: <한 줄 요약>
```

`type`은 저장소 커밋 컨벤션과 동일하게 `feat`/`fix`/`refactor`/`chore` 중 선택한다.

## PR 본문 템플릿

```markdown
## 변경 사항
- 무엇을/왜 변경했는지, 영향받는 엔드포인트·스키마

## 테스트
- [ ] 관련 테스트를 추가/수정했다
- [ ] 프로젝트 테스트 명령 통과 확인 (예: `bun run test`)
- [ ] 마이그레이션이 있다면 롤백 경로를 확인했다

## 체크리스트
- [ ] 입력 검증·에러 응답을 확인했다
- [ ] 인증/인가 경계를 변경했다면 명시했다
- [ ] 기존 API와의 하위 호환성을 확인했다 (breaking change면 명시)
- [ ] 민감정보(키·토큰·개인정보)가 로그·응답에 노출되지 않는지 확인했다
- [ ] 관련 이슈/티켓을 링크했다
```

## 리뷰어

백엔드 팀 동료 1인 이상. 인증/인가나 마이그레이션이 걸린 변경은 시니어 리뷰를 권장한다.

## 강제하지 않는 것

- 디자인 시안 비교, 스크린샷 (UI 변경이 없으면 생략)
